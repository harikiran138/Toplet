## 0. How to read this document

**Nothing in this document says a feature works.** Nothing was built or run (this Mac has no Xcode). Every row only describes what the source code is written to do.

Tags used on every claim:

- **O** = OBSERVED. Followed by `file:line`. I read that line.
- **I** = INFERRED. A conclusion drawn from code I read, not directly stated by it.
- **U** = UNKNOWN. Cannot be decided from the source alone (needs a build/run, a macOS version, or the content of a third-party binary).

Path convention: unless prefixed, paths are relative to `<repo>/Toplet/` (for example `ContentView.swift:715` is `<repo>/Toplet/ContentView.swift`, line 715). `proj:` means `<repo>/Toplet.xcodeproj/project.pbxproj`. `Constants.swift` means `models/Constants.swift` (all `Defaults` keys live there). Settings keys are the string keys of the `Defaults` library (UserDefaults), unless noted `@AppStorage`.

"Public/private API" column: **public** = documented Apple API; **private** = undocumented/private framework, private symbol, undocumented notification or file; **3p** = third-party Swift package (see section 0.3).

### A. Risks and macOS-version sensitivity

1. **Private CGS/SkyLight spaces (A2)**: `CGSSpaceCreate/CGSAddWindowsToSpaces` are resolved with `@_silgen_name`; they can change or disappear in any macOS release. A failure mode is not handled in code (no return-value checks in `CGSSpace.swift:21-40`). Behaviour on macOS 26/27 is U.
2. **Display identity by name (A15, A24)**: screens are looked up by `localizedName` in many places (`sizing/matters.swift:342,382-396,402-409`; `ContentView.swift:2130,2395,2408`). Two identical monitors share one `localizedName`, so closed-notch size, hover rect, `hideOnClosed` and sneak-peek targeting can resolve to the wrong screen (I).
3. **Hover polling is permanent (A11)**: one Task per window ticks at 1 s even when nothing is happening (O :2195-2203). Small, but it never stops while the window exists.
4. **`resizeWindow(animated:)` ignores `animated` (A12)** (O `DynamicIslandApp.swift:670-687`). The visible morph is SwiftUI's; the window frame jumps. A tab with large height change could clip for a frame (I).
5. **Menu bar clearance needs Accessibility (A16)** and runs cross-process AX calls with 0.25 s per-element and 1 s total deadlines (O `MenuBarLayout.swift:121-135`). Without trust the feature silently does nothing (O :111-114).
6. **Notch width clamping**: `enforceMinimumNotchWidth()` rewrites the user's stored `openNotchWidth` when tab count changes (O `matters.swift:152-162`, called `DynamicIslandViewCoordinator.swift:237,242`); the setting is not a pure user preference.
7. **Fullscreen detection (A20)** depends on MacroVisionKit internals (U) and the `AXFullScreen` attribute; behaviour across Stage Manager / Spaces / macOS 15+ is U. Default `nowPlayingOnly` hides the notch only when the playing app is fullscreen (O :100-104).
8. **Lock notification names (A28)** are private. If a macOS release stops posting them the code has a fallback (`CGSessionCopyCurrentDictionary` polling, O `managers/LockScreenManager.swift:352-400`).
9. **Global shortcut and scroll monitors**: Carbon hotkeys (KeyboardShortcuts) and mouse-class global monitors are believed not to need Accessibility (I); the key-event tap in D (media keys) does (see Area D).
10. **Deployment target 14.6** is stated; any API newer than 14.6 used unguarded would fail to compile on older SDKs, but I did not compile (U).

### B. Risks and macOS-version sensitivity

1. **MediaRemote on macOS 15.4+**: direct private MediaRemote access by third-party apps is restricted on newer macOS; the project works around it with perl plus a prebuilt adapter (O `NowPlayingController.swift:273`). That is why the default controller switches to Apple Music on 15.4+ (O `Constants.swift:1529-1535`). Amazon/TIDAL/Cider use the same private route without the deprecation check (O `AmazonMusicController.swift:62-110`; `MusicManager.swift:848-855` only guards `.nowPlaying`). Whether that route works on the running macOS is U.
2. **Opaque binaries** (adapter framework, test client) are loaded into/executed by the app; provenance and build recipe are not in the repo (U). The perl script is BSD-licensed third-party code (O header of `mediaremote-adapter.pl`).
3. **Spotify `sp_dc` / TOTP / Canvas (B7)**: stores a login cookie and tokens in plaintext UserDefaults, fetches secret material from a third-party GitHub repo, and spoofs a mobile client UA. It is opt-in (needs a pasted cookie) but is the highest ToS/credential risk in A to D.
4. **Placeholder metadata**: `MusicManager` initial values are `"I'm Handsome"`, `"Me"`, `"Self Love"` and a heart image (O `MusicManager.swift:569-571,105-108`); with auto-hide off the notch player intentionally shows these (O settings caption). Not real data.
5. **Simulated visualizer**: the default bars are random (O `MusicVisualizer.swift:100`). They look like audio activity but are not.
6. **Network egress when Lyrics/explicit flag/artwork fallback are used**: track title + artist go to lrclib.net, music.163.com, itunes.apple.com, open.spotify.com. `NSAllowsArbitraryLoads = true` (O `Info.plist:5-9`) disables ATS for all of it.
7. **Apple Music relaunch risk (B4)** and AppleScript `try` blocks returning "Unknown"/"Not Playing" strings (O `AppleMusicController.swift:396`, `SpotifyController.swift:375`), which `hasActiveSession` filters (O `MusicManager.swift:584-598`) but `PlaybackState.title` defaults also appear in logs.
8. **MusicKit prompt**: with defaults (Apple Music + `lockScreenMusicFullscreenVideoArtwork = true`) the first track change calls `MusicAuthorization.request()` (O `AnimatedArtworkManager.swift:105-111`), which likely raises a permission prompt even if the user never opens the lock screen (I). A locally signed build may not have a MusicKit developer token (U).
9. **Permission prompts to expect (I)**: Automation (Music/Spotify), Accessibility (TIDAL, plus later areas), Audio capture (waveform, per-app volume), Media & Apple Music (MusicKit).
10. **YouTube Music localhost port 26538** is hard-coded; any other local process can answer on that port if the real app is absent (I).

### C. Risks and macOS-version sensitivity

1. **AppleSMC, IOReport and `pmgr` property names are private** and chip-specific; M5-family key lists and the "M4+ frequency multiplier" (O `utils/IOKitHelpers.swift` `di_convertCFDataToFrequencies`, `isM4` flag) are guesses that need real hardware to verify (U). New chip generations fall to the Intel default list.
2. **Fabricated GPU split and CPU-ranked "GPU processes"** (C9, C10) are display-level inaccuracies.
3. **Per-tick `ps` spawn** while the Stats tab is open costs a fork/exec every interval (C4).
4. **Network labelling** by interface name assumes `en0` is Wi-Fi, which is false on desktop Macs and some configurations (I); the aggregate counter excludes `bridge*` but the per-interface list includes it (O :1281 vs :1182).
5. **Disk throughput** sums every `IOStorage` node; nested nodes could double count (I, not verified).
6. **Memory "used"** subtracts purgeable+external pages, so it will not match Activity Monitor (I from `:895-898`).
7. **Battery event model** (C16) delays state publication and can invent zero state on a failed read (see table).
8. No settings gate for sensors: Stats start only when the tab is visible, so a user who never opens Stats pays no sampling cost (O).

### D. Risks and macOS-version sensitivity

1. **HUD replacement freezes a system process (D4)**: if Atoll is killed or crashes after `killall -STOP OSDUIHelper`, the native volume/brightness OSD stays frozen until the helper is continued or restarted. The code handles normal quit (`DynamicIslandApp.swift:296`, `SystemOSDManager.swift:183-210`) and lock/unlock, but not a hard crash (I). `launchctl kickstart gui/<uid>/com.apple.OSDUIHelper` and `killall -9 OSDUIHelper` assume the label/name exist on the running macOS (U).
2. **Accessibility is required for the HUD replacement (D2, D3)**: without it the event tap cannot be created and the code retries then gives up (O `MediaKeyInterceptor.swift:237-273`); the native HUD keeps showing, so users see no change rather than a clear failure.
3. **Brightness/backlight stacks are private and multi-fallback (D3)**: CoreBrightness class names have changed across macOS releases (the client probes four candidate names, O `CoreBrightnessDisplayClient.swift:37-45`); fallback value 0.5 can be shown as a real level (C table).
4. **Brightness HUD at start-up (I)**: `SystemBrightnessController.start()` emits the current level at once (O `SystemMediaControllers.swift:~686-700`, `notifyCurrentBrightness`), and the observer sets its callback before `start()` (O `SystemChangesObserver.swift:116-122`), so a HUD may flash when the observer (re)starts. U until run.
5. **Focus detection (D12) rests on private notification names, undocumented JSON files and unified-log message formats**; log content for other processes can be redacted and typically needs privileges (U). Default mode needs Full Disk Access to be accurate (O `DoNotDisturbManager.swift:192-203`). Both modes are likely to break across macOS releases.
6. **Screen recording (D7, D8)**: relies on private `CGSIsScreenWatcherPresent` and notification ids 1502/1503; the stop button synthesises Command-Control-Esc (System Events + CGEvent) and kills `screencapture`; it can stop a user's recording by design.
7. **Bluetooth (D16)**: a permanent 3 s poll, repeated subprocesses (`system_profiler`, `pmset`, `ioreg`) and a long-running `log stream` child; initial `system_profiler` call historically deadlocked the main thread (comment at `BluetoothAudioManager.swift:136-160`). Only audio devices are tracked; keyboards, mice and other Bluetooth devices are filtered out (O :543-566).
8. **Battery (D1)**: failure -> default 0% state can emit a false "low battery"; Low Power Mode shares the low-battery HUD (O :112-119).
9. **Extensions (D23)**: a local WebSocket server runs even if the user never installs an extension; the code binds loopback only and requires per-bundle authorisation, but the bundle id is self-asserted by the client (O comment `ExtensionRPCServer.swift:28-32`). Authorisation entries and rate-limit records are stored in UserDefaults.
10. **Lock-screen drawing (D20)** depends on 3p SkyLightWindow plus private lock notifications; behaviour with macOS 26+ lock screen is U.
11. **Connectivity HUD (D17)** has no off switch and SSID retrieval may be redacted without Location access (I).
12. **No uniform timeout/priority arbitration** between simultaneous activities beyond the static if/else chain (A18): a lower-priority activity is hidden, not queued (I).
